# DT_MDP_ErrorPropagation

Code for the paper **"Optimal Sequential Decision-Making for Error Propagation
Mitigation in Modular Digital Twins"** (Najafi et al.).

The repository contains the complete pipeline used for the paper:

1. **Data-driven inputs** – a six-module physics simulator with injected fault
   regimes, ARX surrogates of the modules, a 4-state Gaussian HMM fitted to the
   surrogate residuals and Hungarian-mapped to the regimes. Ten Monte Carlo seeds
   give the baseline transition matrix `A_NoAction` and the observation
   (confusion) matrix `O` (`R/SimulationPipeline.R`).
2. **Decision models** – the MDP (value iteration, continuous-time Bellman
   solution, Gillespie simulators) and the POMDP (Bayesian belief filter,
   point-based value iteration) built on those matrices
   (`R/BaseMDPFormulation.R`, `R/POMDPFormulation.R`).
3. **Baselines and analyses** – MCDA/TOPSIS, k-step heuristic, myopic belief,
   QMDP, Q-learning and REINFORCE agents, the policy summary table and
   statistical tests, the sensitivity and robustness analyses of the revision,
   and the Tennessee Eastman Process transfer.
4. **Figures** – scripts that write every figure of the paper and the
   Supplementary Material.

All paths are relative to the repository root, and a single script
(`run_all.R`) regenerates everything from a fresh clone into `output/`.

## Quick start

```sh
git clone https://github.com/AnniceNajafi/DT_MDP_ErrorPropagation.git
cd DT_MDP_ErrorPropagation
Rscript dependencies.R                  # install the required CRAN packages
Rscript run_all.R --quick               # smoke test, ~6 min (reduced Monte Carlo sizes)
Rscript run_all.R                       # full run with the paper's settings
Rscript run_all.R --download-tep        # full run including the Tennessee Eastman step
```

`Rscript run_all.R --list` lists the steps; `--only=step1,step2` and
`--skip=step` select a subset (for example `--only=pipeline,model,table5`).
Quick mode can also be switched on with the environment variable
`DTMDP_QUICK=1`. Each step runs in its own R process (with `DTMDP_ROOT` set to
the repository root; no script changes the working directory) and logs to `output/logs/<step>.log`;
`output/logs/run_all_summary.csv` records the status and run time of every
step and `output/logs/sessionInfo.txt` the R session.

Individual scripts can also be run on their own from the repository root, e.g.
`Rscript analyses/table5_final.R` or `Rscript R/SimulationPipeline.R`. Every
script locates the repository root itself (from `DTMDP_ROOT` or by searching
upwards from the working directory for `run_all.R`); nothing depends on a
user-specific directory.

The data-driven matrices are regenerated by the first step. With the reference
environment below, the confusion matrix has diagonal
`(0.942, 0.210, 0.799, 0.996)` for (Nominal, SensorNoisy, DynamicsOff, Drift),
i.e. a Nominal accuracy of **0.942** (`output/data_driven/O_confusion.csv`).

## Expected run time

Measured on the reference machine (AMD Ryzen 9 9950X3D, 64 GB RAM, Windows 11,
R 4.5.1):

| Mode | Time |
|---|---|
| `--quick` | about 5 min for the main steps, plus about 3 min for `closed_loop` |
| full | estimated 2–3 h (not timed end to end; see below) |

The data-driven pipeline itself (10 HMM fits) takes about 15 s; one PBVI solve
(200 belief points, 500 iterations) about 13 s. The full run is dominated by
`table5_final.R` (2,000 trajectories for each of nine controllers plus ten RL
agents, about 3 min on 30 cores), `Revision_RewardSensitivity.R` (66 PBVI
re-solves of up to 2,000 iterations), `fig04_sensitivity_analysis.R` (27 PBVI
re-solves and 300-trajectory sweeps), the closed-loop study (about 25 min with
8-10 workers) and the RL sweep (about 7 min on 28 workers; 130 training runs, in parallel on
`DTMDP_CORES` worker processes, default: all cores but two). Quick-mode
numbers are only a smoke test and differ from the paper.

## Tennessee Eastman data

The Tennessee Eastman Process step uses five files of the Russell–Chiang–Braatz
benchmark (`d00.dat`, `d00_te.dat`, `d01_te.dat`, `d11_te.dat`, `d13_te.dat`,
about 3.6 MB). They are not redistributed here. `Rscript tep/download_tep_data.R`
downloads them from a public GitHub mirror of the original Braatz-group files
into `tep/TEP_data/` and checks their MD5 sums (listed in the script); any copy
with the same checksums can be placed there by hand, or pointed to with the
environment variable `DTMDP_TEP_DATA`. Without the data, the `tep` step prints a
message and is skipped, and section 7 of `revision_analyses.R` is skipped.

## Notes on settings

* PBVI uses 200 belief points (4 corners, 6 edge midpoints, 4 face centres, the
  centroid and 185 Dirichlet(1,1,1,1) samples drawn after `set.seed(2024)`),
  an MDP warm start and a fixed budget of 500 iterations. With the data-driven
  `O` the residual plateaus near `1e-2`, so the budget, not the tolerance,
  ends the iteration (`analyses/Revision_PBVI_Convergence.R`).
* All Monte Carlo comparisons start in Nominal with `T = 20 s`; `table5_final.R`
  uses common random numbers (`set.seed(700000 + n)` for trajectory `n` of every
  controller), and the same trajectories feed the statistical tests.
* Each notebook in `notebooks/` reads the script in `figures/` that draws its
  figure and runs it (without its progress messages, see `R/notebook_code.R`),
  so a knitted notebook writes the same PDF as
  `run_all.R` and also shows the figure inline:

  | Notebook | Paper figure | Script |
  |---|---|---|
  | `Fig3_PolicyPerformance.Rmd` | Fig. 3 | `fig03_reward_comparison.R` |
  | `Fig4_Sensitivity.Rmd` | Fig. 4 | `fig04_sensitivity_analysis.R` |
  | `Fig5_ActionMismatch.Rmd` | Fig. 5 | `fig06_action_mismatch.R` |
  | `FigS1_S4_PBVI_RewardSensitivity.Rmd` | Figs. S1, S4 | `Revision_Replot.R` |
  | `FigS2_MDP_Validation.Rmd` | Fig. S2 | `fig01_trajectory.R` |
  | `FigS3_S6_StateOccupancy_DiscountFactor.Rmd` | Figs. S3, S6 | `regen_figures.R` |
  | `FigS5_BeliefTrajectory.Rmd` | Fig. S5 | `fig05_belief_trajectory.R` |

  `MCDA_Methods_Comparison.Rmd` is an additional check that is not part of the
  paper: it replaces TOPSIS in the MCDA baseline by SAW, VIKOR and PROMETHEE II
  (RMCDA) and simulates each on the Table 5 seeds (needs the `table5` step).

  Figures 3, 4, 5, S1 and S4 read saved results, so run `run_all.R` (at least
  the steps `table5`, `pbvi_conv` and `reward_sens`) before knitting them.
  `Rscript run_all.R --notebooks` knits all of them into `output/notebooks/`
  after the other steps. Figures 1 and 2 are diagrams and are not generated by
  code. The notebooks in `notebooks/original_submission/` belong to the first
  submission and do not reproduce the revised results.
